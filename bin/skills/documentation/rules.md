# Skill: documentation-engineering — rules ringkas

1. Tentukan **pembaca** dulu (dev/user/ops) — gaya & kedalaman menyesuaikan.
2. README: apa ini · cara install · cara pakai (contoh nyata) · kontribusi · lisensi. Ringkas & langsung.
3. **Contoh kode harus jalan** (copy-paste-able); jangan pseudo yang menyesatkan.
4. API docs: setiap param/return/error, sebut tipe & default.
5. **Selaraskan dengan kode** — verifikasi nama fungsi/flag benar; jangan tinggalkan dokumentasi usang.
6. Struktur jelas (heading/list), bahasa lugas, hindari jargon tanpa definisi.
